# 常见问题 FAQ

## 1. 忆桥到底是什么？

它是本地优先的长期记忆服务：把 AIRI 对话中的稳定事实、偏好、项目决定等保存
到 SQLite，在以后会话回答前自动召回，并提供 MCP、HTTP API 和管理台。

## 2. 第一次启动为什么什么都没有？

这是正确行为。项目不内置演示记忆或虚假统计，你可以手工新建、导入自己的备份，
或让 AIRI 通过自动生命周期逐步形成真实记忆。

## 3. 超过 1000 条就记不住了吗？

不会。可靠召回不先截取最近 1000 条，而是对全库使用 FTS5、Dense/ANN、概念
倒排、关系扩散和严格重排。规模增长仍会影响延迟和质量，因此要监控水位、评测
和日志，而不是假设无限规模完全免费。

## 4. 为什么不要求用户说“请长期记住”？

AIRI 每轮请求经过兼容代理：回答前自动召回，回答后异步提取。自然表达“我喜欢
深色界面”也可以成为候选；显式记住/纠正/遗忘只是更高优先级快车道。

## 5. 只配置 MCP 就能自动记忆吗？

不能。MCP 提供可调用工具；确定性的每轮自动召回/沉淀依赖 AIRI 把聊天请求发到
`http://127.0.0.1:3789/ollama-compat/v1`。

## 6. MCP 和 HTTP API 有什么区别？

MCP stdio 面向支持 MCP 的 AI 客户端，一个进程固定一个 principal；HTTP API
面向管理台、脚本和集成，通过 Bearer Token 鉴权。两者读写同一 SQLite。

## 7. qwen2.5:14b 是必须的吗？

不是。它是开发验收默认模型，成本低且能在本机运行。AIRI 聊天模型可用
`MEMORY_BRIDGE_AIRI_CHAT_MODEL` 独立替换，其他模型角色也有各自配置。更换后不需迁移
数据库，但旧质量结论不自动继承，必须重跑真实正反例、兼容层探针和桌面闭环。

## 8. bge-m3:latest 用来做什么？

用于 embedding 和 Dense generation。它不是聊天模型。换 embedding 需要新建
generation、全量回填、固定评测、原子切换并保留回滚。

## 9. shadow 和 auto 有什么区别？

- `shadow`：自动提取，但候选进“待确认”，不直接成为规范记忆。
- `auto`：只有满足 namespace 质量、置信、重要度、敏感和关系门禁的候选自动提交。
- `off`：关闭自动提取处理。

首次部署建议 `shadow`。

## 10. 它会把所有聊天都存下来吗？

生命周期账本会保存对话证据以支持提取和追溯，但规范长期层只接受可独立理解、
跨会话仍有价值的原子事实。你可以配置证据 TTL、归档和物理清除。

## 11. 能支持多个账户吗？

可以。principal 是强隔离边界，每个账户使用独立 Token。记忆、trace、反馈、
队列健康和 Doctor 结果按 principal 过滤。

## 12. 同一账户能有多个聊天角色吗？

可以。personal 记忆同账户共享；role 记忆绑定 persona；session 只属于当前聊天；
project 只属于结构化绑定的项目会话。

## 13. 作用域冲突时用哪条？

相同规范谓词按 session > role > project > personal 遮蔽。更具体的当前上下文优先，
不同谓词仍可共同召回。

## 14. 为什么切换 project 必须新会话？

为了避免旧会话把 A 项目记忆突然解释成 B 项目。session 的 project 绑定不可变；
fork 继承原 project，不能在请求里重绑。

## 15. 为什么召回会是 0 条？

可能是 scope/namespace 不对、目标未索引、语义/重排门槛拒绝、被 tombstone、
或可靠语义链不可用。看 qualityState 和 trace 九阶段，不要直接放宽全局阈值。

## 16. `full + 0` 是错误吗？

不一定。它表示可靠链完成但没有结果通过门槛；负例和隔离查询应该返回 0。

## 17. `unavailable` 是什么？

embedding/重排等可靠语义链不可用，本轮不把宽松词面结果冒充可靠记忆。先修复
Ollama、模型或 Dense 状态。

## 18. 反馈会不会把错误记忆越推越高？

反馈只在相关性门槛之后提供最大 0.04 的有界先验，不能把明确无关候选越过严格
重排门槛。错误结果应带 traceId 提交 rejected。

## 19. 记忆纠正后旧内容去哪了？

UUID 保持不变，新内容形成新 revision，旧版本和证据保留并关闭当前有效期。管理
台详情可查看或回退历史版本。

## 20. 删除、遗忘和物理清除有什么区别？

- 删除/遗忘：soft delete + tombstone，立即停止召回，可安全恢复。
- 物理清除：异步擦除正文、证据、索引和相关派生数据。
- 归档：保留但退出普通召回，可取消归档。

外部备份不会被数据库物理清除自动删除。

## 21. 为什么恢复删除记忆有时要二次确认？

旧事实可能与当前单值事实冲突。服务先返回冲突快照和确认 Token；你确认 replace
后才原子恢复，避免旧事实无提示覆盖新事实。

## 22. 记忆压缩会产生幻觉吗？

派生巩固逐句绑定来源并验证支持。无来源句 quarantined，来源变化后摘要 stale。
它不删除原子版本，因此可以追溯和重建，但模型错误风险仍需评测和人工治理。

## 23. 数据会上传到云端吗？

默认不会：HTTP、MCP 和 Ollama 都在本机。但如果你把 Ollama URL 或 AIRI 模型
改成远程服务，相关内容可能离开本机，隐私取决于该服务商。

## 24. 管理台刷新后为什么还要输入 Token？

Token 只保存在页面内存，刷新会清除，这是避免长期写入浏览器存储的安全选择。

## 25. Token 忘了能找回吗？

不能恢复旧明文。使用本机身份 CLI 为该 principal 签发新 Token，再撤销丢失凭据。

## 26. 数据库可以直接用 SQLite 软件修改吗？

不建议。身份触发器、迁移 ledger、版本引用和任务链有严格不变量。直接修改可能
让服务 fail closed 或产生不可追溯状态。使用管理台/API/CLI，并先备份。

## 27. 如何判断系统真的健康？

不能只看 `/api/health`。还要看 system health、Dense lag、未解决 dead letter、
retrying、outbox、日志连续失败、SQLite integrity/FK 和 Memory Doctor。

## 28. 为什么有 pending job 但系统仍健康？

retention/consolidation 周期任务会按未来时间排队，pending 是正常。异常是已过期
任务长期不执行、retrying 增长或未解决 dead letter。

## 29. 备份能恢复到另一个账户吗？

JSON v3 要求 backup userId 与当前 principal 相同，不能靠改 JSON 冒充跨账户迁移。
整机迁移使用一致性 SQLite 备份并保护全部账户/凭据。

## 30. 当前算可以上线吗？

当前不能判定为生产上线 PASS。P0/P1 已编码完成，可用于本机开发和 `shadow`；当前唯一
明确阻断是尚未重跑真实 AIRI 桌面 UI 闭环。重排的 14B 发布门禁在固定负载下 20/20
正确，保守 P95 1313.867 ms、后续复跑 P95 956.240 ms，但这不是日常聊天端到端 SLA。
未来 AIRI、模型、prompt、身份头或 schema 变化后仍必须按测试文档重新验收。

## 31. 为什么 AIRI 有时只回“不知道。”，或以“根据长期记忆”开头？

这是私有事实的确定性抗幻觉门禁。可靠召回有事实时，兼容层确保回答不被
模型换值；full 零召回时精确弃答。世界知识、教程和建议不受该门禁影响。
若结果不符合预期，保留响应头的 requestId/traceId 后查看九阶段 trace。
